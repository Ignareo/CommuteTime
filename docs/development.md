# 开发者指南

本工具是**纯静态前端**：无构建、无后端、无框架，除高德 JS API 与两个 CDN 库外零第三方依赖。克隆下来用任意静态服务器打开即可。

## 本地运行

```bash
python3 -m http.server 8931 --bind 127.0.0.1
# 打开 http://127.0.0.1:8931/index.html    主工具
# 打开 http://127.0.0.1:8931/metro.html    地铁可达性
```

改动后建议按 [验证清单](#测试与验证) 逐项自查（含移动端抽屉、无密钥降级、深链接等）。

## 高德密钥配置

调用高德 JS API 需要 `Key`（JS API）与 `安全密钥（securityJsCode）`。**本仓库 `config.yaml` 已默认预配置好一份可用密钥，克隆后开箱即用**，无需任何设置。

密钥**不在页面展示**：两个页面都没有常驻的密钥设置面板，也不回显已保存的密钥。入口只有两个——无密钥首访/密钥失效（如 `INVALID_USER_DOMAIN`）时自动弹出的引导弹窗，以及页脚不显眼的「重新配置密钥」链接（弹窗输入框不回显已有值）。

运行时的密钥解析优先级为：

1. `localStorage`（用户在弹窗里保存过的）
2. `config.yaml`（静态文件，页面加载时 fetch）
3. 弹窗引导输入（兜底，仅当上面都没有时）

> ⚠️ `config.yaml` 是静态文件，部署后浏览器可以直接下载；且 JS 调用高德时 key 必然出现在网络请求里，**纯静态站无法真正隐藏密钥**。真正的防盗手段是高德后台的「域名白名单」+ 配额限制。公开仓库**不要**提交真实密钥；公开部署建议通过 CI 注入或让用户自备。

### 自行申请密钥

1. 前往 [console.amap.com](https://console.amap.com) 注册登录。
2. 「应用管理」→「创建 Key」，服务平台选 **「Web端(JS API)」**。
3. 复制 Key；在 Key 的「安全设置」里获取 **安全密钥**。
4. 填入首访弹窗点「保存并开始使用」（存 `localStorage`），或写入 `config.yaml`。

`config.yaml` 还包含地图初始视角（GCJ-02，与高德一致）与近似圈配速：

```yaml
amap_key: "你的 JS API Key"
amap_code: "你的安全密钥"
mapbox_token: ""                 # 仅 Mapbox 圈用，公开 pk token 即可，可留空
walk_speed: 4.5                  # 步行近似圈配速 km/h（页面无配置入口）
ride_speed: 9                    # 骑行近似圈配速 km/h（页面无配置入口）
map_center: "121.4997,31.2397"   # 经度,纬度（默认上海陆家嘴）
map_zoom: 12
```

**Mapbox Token**（仅驾车/骑行/步行(Mapbox)圈用）只能写入 `config.yaml` 的 `mapbox_token`，页面无配置入口；旧版本存过 `localStorage.mapbox_token` 的仍会被读取。配速同理：`walk_speed` / `ride_speed` 是开发者配置（缺省/越界回落 4.5 / 9），方案包仍会携带速度以保证几何缓存命中。

`metro.html` 在无密钥时可跳过弹窗纯数据浏览（地图区显示占位层，排行榜/单站列表可用）。

## 技术栈与约束

- 单文件页面：HTML + 内联 CSS/JS；JS 用 `var` + `function` 风格；UI 文案为中文。
- 两个页面共享同一套密钥加载、`#toast`、`#progBar`、配色与深链接写法，改动时注意两侧一致。
- 例外依赖（仅 CDN script，无构建）：
  - 高德地图 JS API 2.0；
  - `polygon-clipping` —— 交集/差集几何裁剪；
  - `lz-string` —— 等时圈几何压缩缓存。

## 底层算法与机制

### index.html（实时计算）

等时圈按交通方式走不同分支：

| 方式 | 实现 | 成本 |
|---|---|---|
| 地铁 / 公交 / 地铁+公交（数据源=旧到达圈） | 高德真实路网**到达圈**（ArrivalRange） | 1 次/圈，上限 60 分钟 |
| 地铁 / 公交 / 地铁+公交（数据源=实时线网） | 现查站点/线路后按到达时刻**逐站松弛** | 约 40~90 次/圈，30~60 秒；时长可到 120 分钟（预算封顶，长圈范围可能偏保守） |
| 步行 / 骑行（默认） | 按 config.yaml 配速画**直线近似圈**（圆环 72 点） | 0 次，即时 |
| 步行 / 骑行（勾选「精确路网圈」） | 真实路径**逐方向二分**边界 | ≈200 次/圈，约 30~60 秒 |
| 驾车 / 骑行 / 步行(Mapbox) | Mapbox 等时圈接口 | 需 Mapbox Token，上限 60 分钟 |

- **精确路网圈**（`buildPreciseRing`）：以起点为中心取 `24` 条方向射线，每条射线在 `[0, maxR]` 内做 `8` 步二分，逼近「耗时 ≈ 目标时长」的边界点；`4` 路并发，扫描上限按 1.8 倍绕行系数估计。凑够 ≥6 个边界点后闭合平滑。
- **实时线网圈**（`buildTransitPreciseRing`）：高德 `ArrivalRange` 的线网数据更新滞后（上海 18 号线二期整段缺失），故改为现查线网后最短路松弛——
  1. `PlaceSearch` 地铁站(150500)/公交站(150700) 取起点步行范围内的站点，站点 POI 的 `address` 即途经线路名（地铁写「1号线;18号线」）；
  2. 线路名 → `AMap.LineSearch`（extensions all）拿站序与折线（接口只按一个方向给站序，代码再按相反方向补一条，否则中间站只能往一边坐车），按相邻站直线距离折算用时。**速度优先用导航反算的逐线值**：`AMap.Transfer` 的乘车段带 `distance/time`，反算该线含停站有效速度（18 号线约 37km/h、11 号线约 43km/h、慢速公交不到 6，统一常数差 3~7 倍）；只累加 ≥2.5km（地铁）/≥2km（公交）的长区间样本，速度落在 25~60 / 4~30 km/h 之外视为混入候车的脏样本直接丢弃；学不到逐线值时退回先验 `TP_SPEED`（地铁 35、公交 12）。早期版本按站另加 25/20 秒停站，等于重复计停站，已删除；
  3. 以「到达时刻」为键的小顶堆做松弛：从站点上车计候车 + 从站体到站台的步行（同名异线站点坐标可差百余米），站间步行 ≤400m 可换乘（计步行 + 60 秒进出站），每条变体只沿自己的站序向前；
  4. 每条查到的线路都会**写回沿途站点**（`addLineTo`）并对已出队的站点重新入队：两条已加载线路的交点自动成为换乘点，不需要额外请求；站点线路表（`PlaceSearch` 半径 420m）只用于发现**尚未加载的新线路**，且**只对地铁站补**——公交站每坐一条线就会带出几十个待查站，配额会瞬间打满；预算 `TP_MAX_AREA`（45 分钟约 35 次）/ `TP_MAX_LINE_*` 随时长缩放，线路检索额度只计真实请求，缓存命中的线路不占额度，用尽后没查过的站点只剩已加载线路，`__tpDebug` 的 `loadedLines`（已加载线路名）、`areaLeft`（剩余预算）、`blindCount/blindSample`（没查过线路表且只挂一条线的站）用于判断换乘是否齐全；
  5. **导航复核（范围与采样）**：模型收敛后把估值 ≤ 1.18 倍软地平线的站列入候选池，**不设 ±22% 窄带**——真实 80 分钟的站若被模型估成 45 分钟，窄带永远碰不到它。候选先按「是否会改变边界」分池：路径上所有线路都已学到速度、且估值 × 最大修正上限（`max(TP_NAV_BIAS_MAX, TP_LINE_BIAS_MAX)`）仍 ≤ 目标的站确定在内，只留**还没有单线样本的线路**各一个（最多 `TP_NAV_CAL_MAX` 个）作校准样本，其余名额全给可能翻进/翻出的站；边界池再按固定时间桶分层（远端桶名额递增），避免「模型 30 分钟、实际 90 分钟」的离群站躲开采样。**最远一桶（模型已超目标 3% 以上）不随主波查询**：等主波样本算出偏差与逐线因子后再决定，校准后估值仍超目标且该线已有单线样本的站直接跳过（两项系数 ≥1 时校准只会更远），模型偏悲观或样本不足 6 个时才继续查。首轮上限仍是 `TP_NAV_CAP_MAX`（按 `16 + 1.2 × 分钟` 缩放，60 分钟圈 88 次）。逐个查 `AMap.Transfer` 门到门时间，覆盖该站到达时刻并作为 Dijkstra 锚点**清空 `best` 重跑一遍**（就地 push 只能让时间变小，「导航说更慢」的修正必须清空重跑才能沿线传下去；第二遍线网全在内存，零 API）。地铁圈只认全程轨道方案，公交圈走 `NO_SUBWAY`。已复核站的「导航/模型」比值取 60% 分位（限幅 0.9~1.5）作为未复核站的接驳/候车系数 `navBias`，导航全失败时用 1.12 安全余量。系数在第二遍松弛里通过 `timeScale` 乘到候车、站台步行与接驳上，**不再在 `finish()` 里乘最终时间**——锚点站已被导航原始时间重写，最终再乘会造成双重收紧，把临界站（18 号线御桥）误推出圈；没有锚点时也必须跑第二遍，否则系数不生效。逐线修正只用**单线路径**的复核样本反解 `导航 ≈ 全局系数×接驳 + 线路因子×乘车`，按乘车时长加权、向全局系数收缩后写入 `lineScales`，第二遍只缩放该线乘车时间；多线路径的误差分不清归属，不参与估计。第二轮**只补被系数挤出圈、且超时不超过 20% 的站**：按「最后乘坐线路」分组，每条线只查最接近边界的一个 + 中位数一个（`TP_NAV_REFINE_PER_LINE`），其余站用该线的导航/模型比值修正，不再逐站花请求；分组用的估值与第二遍同口径（接驳 × `navBias`、乘车 × `lineScales`），线路因子大于全局系数时不会把实际更远的站误算成近失。`TP_NAV_REFINE_CAP`（默认 120）只作异常情况下的硬上限。已在圈内的站不占名额，查了只会缩小圈。`__tpDebug.rejected` 记录圈外近失站的 `model/nav/verified/final`，用于判断到底是被系数误伤还是导航确认到不了。导航一次返回多套方案时，挑其中符合圈类型且用时最短的一套、所有方案都拿去学逐线速度——同一份响应，零额外调用；该方案里每个乘车段的下车站按「段用时累加」登记为免费锚点（`navMid`，作为第二遍种子与门到门时间上界，不写 `navSec`），换乘站因此无需额外请求就有一个真实到达上界。导航结果按 `城市|工作日/周末|圈类型|起点网格(约 150m)|站点` 缓存 3 天。
  6. 几何 = 起点步行盘（时长 × 配速 / 1.3 绕行）+ 各可达站的剩余步行盘（上限默认由 `config.yaml` 的 `station_walk_max_m` 给出，用户也可在公交/地铁数据源行的「下车后步行上限」输入框修改，值存 localStorage 且优先于 config；默认 900m、硬上限 2000m，即约 15.6~35 分钟步行），栅格 100m + marching squares 合并。**不填充线路折线走廊**：人只能在车站下车，区间内任意一点并不具备「下车后继续步行」的能力，把它算进来等于凭空放大圈；因此几何常是多个分离斑块，候选点判定与渲染都已支持多多边形。站间里程按线路折线累计而非站点直线相连，避免弯折线路低估里程。
  几何缓存签名 = `TRANSIT_PRECISE_VER` + 出发时间桶 + 步行配速 + `tpSpeedSig()`（该城市已学线路速度的指纹），学到新线路就自动失效；导航复核的公交结果按工作日/周末分桶缓存，因为 Transfer 只按「当前时刻」规划，平峰样本不能当早高峰结论（地铁不受时段影响）。查询城市以起点附近站点 POI 的 `cityname` 为准（LineSearch 按城市查，用错城市会取到外城同名线路）；每次运行的摘要（预算、调用次数、失败查询数、导航复核数、剪枝/校准/近失分组/远端跳过/方案内锚点/逐线因子、可达站到达分钟）挂在 `window.__tpDebug`，失败时也留摘要并带 `error` 字段。
- **交集/差集**：勾选若干圈后用 `polygon-clipping` 对多个多边形做布尔裁剪。交集以灰色叠加，差集保留各圈颜色，两个开关可叠加；候选列表与批量通勤跟随显示区域（`regionsActive`）。
- **几何缓存**（`lz-string`）：每圈几何按签名 `circleSig(起点, 方式, 时长, 是否精确, dataMode)` 压缩写入 `localStorage`（键 `house_tool_circle_geom`），按签名做 LRU/TTL，上限 80 条、30 天。实时线网圈的签名额外带算法版本、步行配速、逐线速度指纹（`tpSpeedSig`）与算法指纹（`tpAlgoSig()`，哈希建圈函数源码和关键预算常量），改算法/改配速/学到新线路即自动失效，不必手工递增版本号——只改复核名额却没动版本号时，旧几何会一直命中、新代码从未执行，且 `__tpDebug` 根本不会被创建。命中则零 API 消耗秒装配；配额超限只 toast 提示，不影响使用。**新建/重建圈用当前签名**（所以改了算法的新圈会走新逻辑）；但**恢复存档与导入方案包时以圈保存的 `geomSig` 为准**查缓存并装配，缓存里有几何就直接用、不重新计算——否则代码指纹/速度一变就把已缓存的圈排队重算，白耗配额。方案包导出的几何键也用保存签名，与导入端对齐。
- **刷新选中圈**：高级面板的「刷新选中圈」按当前算法/线网重算勾选的圈：先用当前参数算签名、删掉对应几何缓存，再不带保存签名重建，命中必然 miss 走 API；新几何以当前签名写回缓存与 state。与恢复存档（沿用保存签名不重算）相反，这是用户显式触发的强制重算，会消耗配额（实时圈/精确圈较慢，有二次确认）。
- **实时线网缓存**：线路站序按「城市|线路名」存 `house_tool_transit_line_cache`（lz-string，160 条 / 30 天），站点线路表按「城市|类型|站名」存 `house_tool_transit_stop_cache`（900 条 / 30 天，命中需坐标相差 ≤300m）。两者只省配额，失效最多让下一次查询变慢。
- **通勤计算**：结果缓存相同起点+候选不重复请求；高德接口统一经 `amapRequest` 令牌桶限流，遇限流自动退避重试，配额耗尽明确报错（不会误判为「无公交方案」）。
- **附近车站线路**（`searchNearbyStations`）：PlaceSearch 找公交站(150700)/地铁站(150500)，`AMap.Walking` 逐站算真实步行时间并按设定时长过滤；站点 POI 的 `address` 给出途经线路名（公交「167路;18路」、地铁「1号线;2号线」），再用 `AMap.LineSearch`（extensions all）按名取 `path` 折线与 `via_stops`（含每站名称/坐标，沿途站点零额外请求）。单次最多 24 个候选站（先按直线距离粗筛）、50 条线路（按步行时间由近到远），步行时间与线路走向分别缓存于 `house_tool_station_walk_cache` / `house_tool_station_line_cache_v2`。线路高亮（悬停/点击）通过独立的白色 halo Polyline 实现，沿途站点用去重后的 CircleMarker 绘制；悬停名称用 `#mapTip` 固定定位浮层（不触发 InfoWindow），线路详情用 `stationInfoWindow`（`autoMove:false`）在点击位置打开，避免视野偏移。
- **面积**：环面积按参考纬度做球面近似换算（`ringAreaM2`）。
- **方案包/分享链接**：把起点与圈几何序列化为纯文本（lz-string 压缩），可跨设备导入导出；导入为追加语义，重复项自动跳过。

### metro.html（本地预计算）

数据是离线算好的地铁 N×N 通勤时间矩阵，前端纯静态加载，零 API 消耗、秒开：

- **站点按站名分组**（同站不同线的节点合并），组 id 形如 `g001`。
- **全城视图**：所有站点按「到其他各站的平均通勤时间」上色，附排行榜。
- **单站视图**：点击任一站点或排行行末「›」，用真实站间时间给全城上色，并画 15/30/45/60 分钟等值圈。
- **等值圈为凸包外扩近似**（`convexHull` + `expandHull`）：对同档站点取凸包后按质心外扩作为缓冲，非真实到达面（页脚保留口径声明）。
- **按需分片加载**：`rows/<组id>.json` 只在进入单站视图时 fetch，首屏不加载矩阵。
- **线路折线**：`lines.json`（可选，旧城市数据可能没有）提供每条线的标志色与有序组 id，前端画 Polyline；404 时按无线处理。

- 城市下拉框出现新城市、排行榜有数据、点排行行末「›」（或散点 InfoWindow 的「查看单站视图 ›」）进单站视图，等值圈与可达列表正常。

- 「② 附近车站线路」：选起点与步行时长后查询，车站点、线路与沿途站点应出现；公交/地铁/途经站复选框可分别显隐；悬停或点击线路出现白色描边高亮，点击站点可看经过线路；同参数重复查询应明显更快（命中本地缓存）。
